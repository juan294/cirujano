# Phase 5: Sandbox verifier for push guards

## What runs in the Sandbox

A new trusted harness `scripts/optimization/push-guard-harness.mjs`, offline, in one disposable
instance. The harness bytes and hash are bound into a **new image**; the existing `harness.mjs`
bytes are unchanged. Payload: base workflow, candidate workflow, a fixture set generated by the
tool (hashed) and the expected results. Upload uses the existing `/v1/files` path; the 1 MiB
request limit is respected.

```
@ verifyPushGuards(payload) -> envelope
ctx: guard-expression evaluator, push-classifier template (extracted from candidate bytes)
pre: payload digests match profile; network disabled
do:
  1. validate base/candidate inverse (validateGuardOnlyChange)
  2. compute job run/skip decisions across the decision matrix for base and candidate
  3. run the extracted classifier script per fixture (node --import fetch-stub; no network)
  4. emit canonical envelope: cells checked, mismatches (first 20), script digest, fixture digest
fail: any mismatch, missing cell, script digest != classifierDigest -> failed
```

Decision matrix: event ∈ {push validated, push not validated, pull_request, workflow_dispatch,
schedule} × classifier result × original need results × opaque original condition. Expected:
candidate == base in every cell, **except** push-validated, where every guarded job is skipped.
The classifier fixture set is exactly the Phase 3 table, run through the **candidate's embedded
script bytes**, not the TypeScript module.

## Contracts and CLI

`ExecutionProfile` gains `kind:'push-guard'`, with an image whose manifest lists both harnesses.
The family `sandbox` artifact has one operation `role:'verifier'`, `matrixCells`, `mismatches:0`,
`classifierCases`, `classifierDigest` and `fixtureDigest`. `verify.ts` dispatches by family. The
permit, journal, polling, cancel and recovery code is reused unchanged.
`scripts/optimization/image-context.mjs` adds the second harness to the build context.

## Local proof

Extend `scripts/optimization/check-harness-linux.mjs` (`verify:optimization-harness-linux`) to
run the push harness on owned fixtures in the cached local Linux image. It needs no pull and no
account calls.

## Tests (first)

`push-guard-matrix-pass`; mutation tests (drop `!cancelled()`, drop need-success, invert the
guard, drop the original condition): each must be detected by a named matrix cell.
`push-guard-mismatch-disclosed`, `push-guard-image-unavailable`, `push-guard-script-tamper`.

## Acceptance

Automated: full gates plus `verify:optimization-actionlint` plus `verify:optimization-harness-linux`.
Manual: none. The image build/import for the new harness is a Phase 7 authorization.
