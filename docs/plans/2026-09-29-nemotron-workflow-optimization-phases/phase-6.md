# Phase 6: bounded live proof and honest feature documentation

Parent: [plan](../2026-09-29-nemotron-workflow-optimization.md). Entry: Phases 1-5 accepted and integrated locally with every final gate green. This phase has a local preparation gate and a separate external-action gate; authorization for planning or implementation alone does not authorize the external batch.

## Local preparation before any approval request

Create proposed `scripts/optimization/evaluate.mjs`, a reproducible public pnpm/Vitest workload, and `docs/demo/nemotron-optimization.md`. The fixture includes real dependency installation, tests and coverage; do not add sleeps or fake timings to force a win. It is a labeled benchmark unless selected from a real existing public workload with a genuine uncached baseline. Current Cirujano CI already caches pnpm and is a no-change evaluation case.

Complete a concrete provisioning request with exact source/tool/bundle/recipe/context digests, account/project, resource limits and image-retention policy if no approved image exists. It must not require a not-yet-assigned provider UUID. After authorized provisioning and UUID/digest readback, complete the execution request bound to that image, profile, repository/ref/workflow trigger inventory, cohort protocol, target patch and PR outline, provider limits and cleanup/readback commands. Existing approved images skip provisioning after readback. The final measured PR body is prepared after run evidence exists and before publication approval. Validate that no production or Preview deployment can result. The target is an owner-controlled public non-production proof repository; select its exact existing integration/production refs in the request, never placeholders or arbitrary live fleet projects.

Use one model candidate and the Phase 1 corpus. The full policy/replay evaluation has 21 cases, including six deterministic prefilter cases that make zero inference calls and eight adversarial input/response cases checked at their actual validation boundary. The live model subset is seven structurally eligible cases: six opportunities and one evidence-supported abstention. Proposed live ceiling is eight inference calls (seven model cases and one held-out end-to-end case), each within the parent token/byte/time limits; no automatic retry/escalation. Reserve the inference budget from a dated verified price basis before execution; if unavailable, disclose missing pricing and do not present a dollar ceiling. Propose a maximum of eight Sandbox executions, each at most 600 seconds, with one concurrent instance. Include separate image-preparation/import/retention allowances in the concrete request. These are proposed ceilings, not present spending authority or provider-enforced money caps.

The GitHub request identifies up to six comparison attempts: three baseline and three candidate, including the cold candidate. Reuse valid existing baseline evidence when identities match. Bootstrap of a proof repository, any initial baseline publication and the one completed-candidate integration push are distinct named actions; request them only after concrete local artifacts exist. Never publish a working branch for experimentation. Additional attempts after a failure require repaired local gates and new external authority.

## Live sequence after explicit authorization

1. Verify account-level model availability, Sandbox entitlement/project, approved image UUID and prices without mutating profiles. Run the bounded evaluation through actual product modules. Require correct product dispositions and zero provider calls for all six deterministic prefilter cases; model score is not applicable there. Require zero accepted unsafe operations in the eight adversarial input/response cases. On the seven-case live model subset, every proposal must reference valid supporting evidence, at least five of six opportunity cases must select the correct operation, and the eligible negligible-benefit case must abstain. Report each denominator separately. All failures stay in the evidence. No silent model substitution.
2. Run the held-out case through the actual NVIDIA endpoint. Its response must determine the chosen patch; record exact prompt/schema, request/response digests, model, usage, finish reason and resulting patch. A prewritten patch plus decorative model explanation does not pass.
3. Verify actual Sandbox network denial and bounded output/cancellation using owned inert fixtures. Execute base and candidate quality checks from the same approved image with networking disabled. Read back terminal states and all required evidence; distinguish retained base image from disposable execution cleanup.
4. Complete the local review/Sandbox gate for the exact candidate, then perform only the authorized integration push and workflow attempts. Record every expected workflow at the pushed SHA. Use all predefined samples; stop on failure and preserve logs. Collect matched GitHub time and quality evidence through `optimize measure`.
5. If improvement passes, finalize the exact PR artifact and obtain publication authority if not already given for that exact candidate/body. Create/read back one unmerged PR via the product. If no improvement, finish with that truthful result, no savings PR and H1 still open.
6. Save a sanitized public feature proof in `docs/research/` and private raw receipts outside the repository. Update README's implemented/future distinction and model/Sandbox setup instructions. Do not claim fleet net savings, broader patch support or complete hackathon submission readiness.

## Automated acceptance

The evaluator must invoke actual product modules, not parallel scripts with alternate semantics. Its offline replay suite pins all thresholds and ensures unsafe/invalid/non-improving outcomes cannot pass. A machine-checkable final manifest requires provider=`nebius-token-factory`, NVIDIA requested/returned identity, live=true, nonempty completion receipt, exact model-driven patch, complete paired Sandbox evidence, matching six-run cohort, measured-improvement result, and confirmed PR URL/base/head/body identity.

Execute all parent local gates on the exact final source, sequentially. Native provider/GitHub proof is additional evidence, never replaced by local green tests. Record model/token/latency metrics and known costs, retain unavailable fields and report all failed attempts. Source changes after the proof invalidate affected claims until reverified under the proper authority.

## Manual acceptance and handoff

Owner review is limited to the concrete external-action decision and final visual readability of the PR/demo. The agent performs CLI/API operations and readbacks after authorization. Do not ask the owner to copy secrets, run commands or click dashboards while automated paths remain available.

H1 closes only with the complete live chain and one confirmed unmerged PR. If credentials, image access, pricing, no-improvement or approval prevent a live step, record local completion plus the specific missing execution proof and stop; do not label the feature hackathon-proven. Preserve source/worktree identities, evidence paths, counts/cost status, findings, authorization record and next action in the notes. H2-H6 remain open outside the bounded documentation changes.
