# Jev capabilities and Cirujano: current-state research

Date: 2026-10-28. Repository: `/Users/juan/code/cirujano`. Branch: `develop`. Base and current source commit: `37e7e33a0ba15d24eaa6433e9a4fa7f00613fb1f`. Working tree was clean before research. Scope: descriptive research requested with `rpi-research`; recommendations are in the companion assessment. No product code, dependencies, configuration or remote state changed.

## Answer

Cirujano already separates bounded model diagnosis from deterministic workflow editing, verification, measurement and publication. Its current model consumes largely numerical facts about two preselected operation families. Jev provides typed semantic judgments and probability distributions, rather than generated patches or explanatory prose. No Jev integration or performance benchmark was executed in this investigation. The existing telemetry supports cost and timing analysis but lacks the source/step/log context needed for semantic causal diagnosis.

## Developer interfaces and measurement


- CLI dispatch covers estimate, runner, telemetry, fleet and optimize. Usage errors are exit 2, runtime failures exit 1, success exit 0; runtime failures are visible on stderr (`packages/cli/src/cli.ts:33`, `packages/cli/src/cli.ts:53`). Command grammar exposes machine-readable JSON and Markdown reports, inspect/status commands and separate mutation commands (`packages/cli/src/args.ts:7`). These are useful surfaces for an advisory question/answer layer without requiring a new hosted UI.
- The GitHub Action currently paginates a workflow run's jobs, computes billable minutes, and emits `billable-minutes` and `job-count`; API/input errors fail the action (`packages/action/src/main.ts:7`, `packages/action/src/main.ts:13`, `packages/action/src/main.ts:21`, `packages/action/src/main.ts:27`). It does not invoke an LLM in this entry point.
- Billing is deterministic timestamp arithmetic, rounded per job; missing or reversed timestamps yield null and increment skipped jobs (`packages/core/src/billing.ts:40`, `packages/core/src/billing.ts:52`). Raw paginated inventories with mismatched total count are rejected (`packages/core/src/billing.ts:74`). Workflow usage ranking is average sampled minutes times run count, descending estimated minutes (`packages/core/src/billing.ts:125`). No semantic model participates in this arithmetic.
- Telemetry collects owned nonarchived repositories with concurrency four across repositories; run-job reads inside each repository are sequential. It reuses completed runs only when identity metadata agrees and prior evidence is reusable, and fetches incomplete timing again (`packages/cli/src/telemetry.ts:239`, `packages/cli/src/telemetry.ts:247`, `packages/cli/src/telemetry.ts:251`, `packages/cli/src/telemetry.ts:257`, `packages/cli/src/telemetry.ts:305`). This reuse reduces network reads relative to fetching all completed jobs again.
- GitHub collection uses authenticated `gh api --paginate --slurp`, a 64 MiB buffer, 120-second initial timeout and 240-second retry timeout. Transient read failures have at most three attempts with 2/8-second waits; final errors name endpoint, attempts and process details (`packages/cli/src/github-api.ts:24`). The implementation classifies these explicit transport errors in code.
- Telemetry preserves run IDs, attempts, job IDs, names, events, conclusions, timing, labels, runner attribution and monetary derivations (`packages/cli/src/telemetry.ts:45`, `packages/cli/src/telemetry.ts:78`). This schema does not retain log bodies, step timings, workflow source or head SHA. Source collection confirms listJobs drops steps and listRuns parses only its defined metadata (`packages/cli/src/telemetry-service.ts:117`, `packages/cli/src/telemetry-service.ts:136`). New semantic explanations of installation/network/build bottlenecks would need additional evidence; names and totals alone cannot establish causes.
- Normalization distinguishes incomplete from not-run jobs; incomplete duration/cost stays null. Public repository hosted cost and counterfactual avoided cost are zero; other self-hosted jobs do not count as Cirujano (`packages/cli/src/telemetry.ts:762`, `packages/cli/src/telemetry.ts:780`, `packages/cli/src/telemetry.ts:813`). Classification here is deterministic runner metadata, not language understanding.
- Store reports require continuous daily observation coverage and reject malformed/mixed-owner snapshots; partial backfill files do not bridge observation gaps (`packages/cli/src/telemetry-store.ts:27`, `packages/cli/src/telemetry-store.ts:48`, `packages/cli/src/telemetry-store.ts:87`). Failures name dates or files. Recovery is supply valid coverage or select a covered window; model judgment cannot repair absent evidence.
- Aggregation deduplicates by job identity, accepts constrained timing completion/visibility changes and rejects conflicting completed evidence (`packages/cli/src/telemetry.ts:380`, `packages/cli/src/telemetry.ts:406`). Unknown or conflicting evidence is not silently averaged away.
- Enrollment reports compute before/after windows, queue p50/p95 from run-created to job-start, provider cost from controller generations and job assignment matches. Missing controller data or unmatched credited jobs mark incomplete; unmatched jobs suppress net savings (`packages/cli/src/telemetry.ts:489`, `packages/cli/src/telemetry.ts:532`, `packages/cli/src/telemetry.ts:546`, `packages/cli/src/telemetry.ts:565`). Queue metric includes upstream run delay; it is not an isolated VM boot latency measure.
- Runner cost requires explicit dated rates, observed bounded compute intervals, disk retention, egress and hosted baseline; it returns a reason when these are missing (`packages/runner/src/cost.ts:6`, `packages/runner/src/cost.ts:42`, `packages/runner/src/cost.ts:74`). Arithmetic is simple and auditable.
- Markdown reports explicitly warn that public repository migration adds provider costs, name incomplete enrollments, and state limits including list prices, no subtraction of private allowance, single-slot VM serialization and a sleeping host (`packages/cli/src/telemetry.ts:678`, `packages/cli/src/telemetry.ts:699`). These are code-rendered caveats, not newly measured facts about a currently running fleet.
- Fleet verification checks live workflow identity against enrollment. Drift produces specific visible guidance: record cutover, review edit and refresh cutover, or enroll afresh. Removal of an enrolled label updates registry status to reverted (`packages/cli/src/fleet-service.ts:217`). Despite its name, it can write registry state (`packages/cli/src/fleet-service.ts:258`); it was not executed.
- Fleet publish writes a sanitized local Markdown file; it does not itself post externally (`packages/cli/src/fleet-service.ts:561`). Its guard refuses names, owner prefixes, controller identity and provider IDs (`packages/cli/src/fleet-service.ts:572`). This sanitization occurs at local report publication, rather than at a general-purpose external inference boundary.
- Runner lifecycle decisions are a pure rule/state flow with precise blocking reasons, permit identity/budget validation, queue/provider completeness requirements, immutable lifetime and authorized recovery (`packages/runner/src/lifecycle.ts:57`, `packages/runner/src/lifecycle.ts:80`, `packages/runner/src/lifecycle.ts:92`, `packages/runner/src/lifecycle.ts:161`). Watch emits status/decision/queue/read-hold JSON (`packages/cli/src/runner-service.ts:261`), direct action emits blocked reason (`packages/cli/src/runner-service.ts:360`). Runner creation, retries, authorization and cleanup follow these code contracts.

## External capability evidence

Primary sources retrieved 2026-10-28; vendor behavior is documented, not independently measured here.

- [Introduction](https://docs.typesafe.ai/introduction): state plus independent typed questions produces structured answers. Choice selects a candidate; Noul returns a truth probability; Score evaluates a described rubric. Questions share state but do not consume each other's answers. Jev is not a text/code generator.
- [Models](https://docs.typesafe.ai/models): current pinned model `jev-1.14.0`, released October 14; latest/preview aliases currently resolve to it. Published price is $0.042 per million input tokens, free outputs. Default context is 64k/request and 32k/question. Opt-in 262k context is documented as slower and less accurate. Organization rate limits require account inspection. The vendor states customer requests/responses are not used for training.
- [Confidence](https://docs.typesafe.ai/confidence): Choice/Score confidence summarizes probability concentration, not independent proof that an answer is correct. Noul has no separate confidence field. Domain thresholds require evaluation.
- [Images](https://docs.typesafe.ai/images): although the models table lists text, image input and Box are available experimentally through a danger-zone header. The vendor explicitly says they are not production-ready. This resolves the apparent discrepancy with SDK/skill image examples.
- [Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13): documented weaknesses include arithmetic, dates, indirection, irrelevant context, adversarial state and option-order effects. This page applies to 1.13, not a measured characterization of 1.14; these remain useful evaluation cases, not proof of unchanged defects.
- [JavaScript SDK](https://docs.typesafe.ai/sdk/javascript): TypeScript types, ESM/CommonJS, Node 22+, v0.7.0 source links. Compression is automatic for sufficiently large requests and requires Node 22.15+. [RetryPolicy](https://docs.typesafe.ai/sdk/javascript/api/interfaces/RetryPolicy) defaults to two retries, including timeout/connection failures; zero disables them.
- [API errors](https://docs.typesafe.ai/api/errors): 32 MiB body limit and finite JSON values; 429 and 529 identify throttling/overload. Typed answers do not eliminate transport or validation failures.
- [Legal index](https://docs.typesafe.ai/legal): enterprise zero-data-retention is offered separately. No account-specific retention agreement was verified; no-training does not establish zero retention.
